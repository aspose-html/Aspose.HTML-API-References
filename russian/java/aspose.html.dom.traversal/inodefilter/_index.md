## INodeFilter interface

Фильтры — это объекты, которые умеют «отфильтровывать» узлы. Если NodeIterator или TreeWalker получает NodeFilter, он применяет фильтр перед тем, как вернуть следующий узел. Если фильтр принимает узел, логика обхода возвращает его; иначе обход ищет следующий узел и делает вид, что отклонённый узел отсутствует.

DOM не предоставляет никаких фильтров. NodeFilter — это просто интерфейс, который пользователи могут реализовать, чтобы предоставить свои собственные фильтры.

NodeFilters не нужно знать, как перемещаться от узла к узлу, и им не требуется знать что‑либо о структуре данных, по которой происходит обход. Это делает написание фильтров очень простым, поскольку единственное, что им нужно уметь, — оценивать отдельный узел. Один фильтр может использоваться с различными типами обходов, способствуя повторному использованию кода.

Смотрите также [Document object Model (DOM) Level 2 Traversal and Range Specification](http://www.w3.org/TR/2000/REC-DOM-Level-2-Traversal-Range-20001113). @since DOM Level 2
