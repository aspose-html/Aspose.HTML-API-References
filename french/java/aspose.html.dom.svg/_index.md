Toutes les classes du package **com.aspose.html.dom.svg** sont basées sur les recommandations SVG2 du W3C. En utilisant ce package, vous pouvez charger, naviguer ou rendre le fichier SVG selon vos besoins.

| [SVGDocument](./svgdocument/) | Un `SVGDocument` est la racine de la hiérarchie SVG et contient l'intégralité du contenu. En plus de fournir l'accès à la hiérarchie, il offre également quelques méthodes pratiques pour accéder à certains ensembles d'informations du document. Lorsqu'un élément ‘svg’ est intégré en ligne comme composant d'un document provenant d'un autre paquet, par exemple lorsqu'un élément ‘svg’ est intégré en ligne dans un document XHTML [XHTML], alors aucun objet `SVGDocument` n'existe ; à la place, l'objet racine dans la hiérarchie d'objets du document sera un objet Document d'un type différent, tel qu'un objet HTMLDocument. Cependant, un objet `SVGDocument` existera bien lorsque l'élément racine de la hiérarchie du document XML est un élément ‘svg’, comme lors de la visualisation d'un fichier SVG autonome (c’est‑à‑d. un fichier avec le type MIME "image/svg+xml"). Dans ce cas, l'objet `SVGDocument` sera l'objet racine du modèle d'objets du document. |

| [SVGTextContentElement](./svgtextcontentelement/) | L'interface SVGTextContentElement est héritée par diverses interfaces liées au texte, telles que SVGTextElement, SVGTSpanElement, SVGTRefElement, SVGAltGlyphElement et SVGTextPathElement. Pour les méthodes de cette interface qui font référence à un indice de caractère ou à un nombre de caractères, ces références doivent être interprétées comme un indice d'une unité de code UTF-16 ou un nombre d'unités de code UTF-16, respectivement. Cela garantit la cohérence avec DOM Level 2 Core, où les méthodes de l'interface CharacterData utilisent les unités de code UTF-16 comme indices et comptes au sein des données de caractères. Ainsi, par exemple, si le contenu texte d'un élément ‘text’ est un seul caractère hors du BMP, tel que U+10000, alors appeler getNumberOfChars sur cet élément renverra 2, car deux unités de code UTF-16 (la paire de substitution) sont utilisées pour représenter ce caractère. |
